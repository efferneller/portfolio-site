# Портфолио Эллады Ярмоновой

Статический сайт по [макету Figma](https://www.figma.com/design/t7c029bCNiqsBtdT2hwSUf/Portfolio?node-id=214-49941): главная страница и три кейса, адаптированные для desktop и мобильных экранов.

## Локальный запуск

Нужен Node.js 22 или новее. Внешних npm-зависимостей нет.

```sh
npm run dev
```

Сайт доступен по адресу `http://127.0.0.1:5173`. После изменения файлов обновите страницу. Другой порт можно задать через `PORT=5174 npm run dev`.

```sh
npm run build
npm run preview
```

Сборка копирует страницы, стили, скрипты и изображения в `dist/`. Каталог сборки не хранится в Git. Исходные изображения находятся в `static/`.

## Изображения без потери качества

Исходные PNG сохранены. Сайт использует меньшие по размеру файлы из `static/optimized/`: lossless WebP либо PNG, если он компактнее. Разрешение и значения пикселей RGBA остаются исходными, включая прозрачность. Имена содержат хеш содержимого и получают годовой браузерный кеш; HTML и манифест продолжают перепроверяться.

Для повторной генерации нужен Python и Pillow 12.3.0:

```sh
python3 -m pip install -r scripts/requirements-images.txt
npm run images:optimize
npm run images:check
```

Проверка `--check` сверяет размеры, пиксели и контрольные суммы без изменения файлов. Соответствия исходных URL и оптимизированных файлов записаны в `static/optimized/manifest.json`. Исходный HTML сохраняет ссылки на PNG: сборка и локальный сервер автоматически подставляют пути из манифеста. Менять HTML вручную после генерации не нужно.

Оптимизированные файлы и манифест хранятся в Git. Сборка проверяет контрольные суммы исходников и результатов; после изменения PNG сначала повторите генерацию. Обычная сборка использует готовые файлы и не требует Python или Pillow.

Экран загрузки показывает прогресс и открывает страницу после загрузки и декодирования всех её изображений и готовности шрифтов. При ошибке доступна кнопка «Повторить». Возврат из кейса восстанавливает положение на главной после завершения загрузки.

## Ветки и публикация на REG.RU

- `dev` — разработка и проверка; публикация не запускается.
- `main` — публикация на https://efferneller.ru/ через GitHub Actions.

Хостинг: REG.RU, Хост-0, ispmanager. Публикация использует **FTPS**
(FTP с явным TLS, порт 21), SSH не требуется.
Сервер `server26.hosting.reg.ru` указывает на `31.31.196.4`; его TLS-сертификат
проверен для этого имени. Логин — `u3700684`, папка FTP — `/www/efferneller.ru`.
Путь из панели ispmanager может отличаться от пути внутри FTP: перед записью
сценарий проверяет существование папки и её `index.html`, при ошибке останавливается.

Workflow `.github/workflows/deploy-reg.yml` собирает сайт на Node.js 22 командой
`npm run build`, проверяет сценарий загрузки и запускает `scripts/deploy_reg.py`.
На хостинге Node.js не нужен. Нужен Python 3 только на GitHub runner; внешних
Python-зависимостей нет.

### Однократное подключение

1. В GitHub открыть репозиторий → **Settings → Secrets and variables → Actions →
   New repository secret**. Имя: `REG_FTP_PASSWORD`, значение: пароль FTP-пользователя
   `u3700684`. Пароль вводится только в GitHub; не сохраняйте его в файлах репозитория.
2. Перенести блок `BEGIN portfolio cache` из корневого `.htaccess` репозитория
   в существующий `.htaccess` папки сайта, сохранив правила SSL и хостинга.
   Если файла нет — загрузить этот файл один раз. Автопубликация исключает
   корневой `.htaccess`, чтобы сохранять настройки, созданные в ispmanager.
   Сборка включает его в `dist/` для первоначального ручного переноса.
3. Перенести проверенные изменения из `dev` в `main`. Push/merge в `main`
   запускает публикацию автоматически. Ручной запуск: **Actions → Publish to REG.RU →
   Run workflow → main**. Для другой ветки job публикации пропускается.
4. Проверить главную, все кейсы и HTTP-заголовки: HTML/CSS/JS —
   `Cache-Control: no-cache`, изображения с хешами — годовой `immutable` кеш.
   Если статику отдаёт nginx в обход Apache, кеширование нужно задать также
   средствами панели REG.RU и повторить проверку заголовков.
5. После успешной проверки REG.RU отключить сборки Netlify:
   **Project configuration → Developer settings → Continuous deployment →
   Build settings → Configure → Stopped builds**.
   Файл `netlify.toml` оставлен до завершения перехода; изменение файлов Git
   само по себе не отключает Git-интеграцию Netlify.

### Поведение загрузки

Содержимое `dist/` отправляется прямо в папку сайта. Изображения с хешами,
которые уже есть на сервере и совпадают по размеру, пропускаются; оригинальные
PNG из манифеста не загружаются, страницы используют оптимизированные варианты.
Остальные файлы обновляются при каждой публикации, даже если размер не изменился.
Ресурсы отправляются до HTML. Каждый файл загружается под временным именем
и заменяет опубликованный только после успешной передачи.
Старые файлы и папки на сервере не удаляются.

Локальная проверка сценария без подключения к серверу:

```sh
python3 -m unittest discover -s tests
```

До добавления секрета, проверки FTP-пути и первого успешного запуска workflow
автопубликация не считается подключённой. Доступ к FTPS проверен без авторизации;
доступ к файлам и параметры кеша проверяются после подключения.

Справка: [GitHub Secrets](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets),
[корневая папка REG.RU](https://help.reg.ru/support/hosting/razmeshcheniye-sayta-otobrazheniye-v-brauzere/kornevaya-papka-sayta).
